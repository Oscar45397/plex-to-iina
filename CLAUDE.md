# Plex → IINA

Browser extension (Chrome + Safari on macOS) that sends Plex Web's Play buttons to IINA,
streaming the original file from Plex Media Server, plus an IINA plugin that reports
playback progress back to Plex. See README.md for how it works and the project layout.

This is a **public repository** (github.com/s7zjg7r9wf-cell/plex-to-iina). Everything
committed is visible to anyone, forever, so the rules below apply to every commit.

## Never commit personal or environment data

Before every commit, check the staged diff for, and remove:

- Real names, email addresses, usernames other than the GitHub handle
- Apple Developer team IDs, signing identities, provisioning details
  (`safari/build.sh` reads the team from the keychain at build time; keep it that way)
- Server addresses, IPs, hostnames, Plex machine identifiers, NAS or library names
- Plex tokens (`X-Plex-Token`), plex.tv account data, cookies, logs that contain them
- Screenshots or test media from the user's own library

Quick check before committing:

```bash
git diff --cached | grep -inE 'token=[a-z0-9]{8,}|@gmail|192\.168\.|10\.[0-9]+\.[0-9]+\.|machineIdentifier=[0-9a-f]{20,}|DEVELOPMENT_TEAM = [A-Z0-9]{10}'
```

Commits use the repo's local git identity (the GitHub name and its no-reply email). Don't
change it, and never commit with a personal email address.

## Commit messages

Use Conventional Commits with these types, so the history reads as a change log:

| Type | Use for | Changelog section |
|---|---|---|
| `fix` | Bug fixes: something that didn't work as intended now does | Fixed |
| `feat` | New features or new user-visible capabilities | Added |
| `qol` | Quality-of-life improvements to existing features: smoother, clearer, fewer clicks, better defaults, better messages | Improved |
| `perf` | Faster playback start, less memory or network use | Improved |
| `docs` | README, CLAUDE.md, comments only | (not listed unless user-facing) |
| `refactor` | Code changes with no behaviour change | (not listed) |
| `test` | Test tools and mock servers (`tools/`) | (not listed) |
| `build` | `safari/build.sh`, Xcode project, packaging the plugin | (not listed unless user-facing) |
| `chore` | Versions, housekeeping | (not listed) |

Format:

```
<type>(<scope>): <what changed, imperative, ≤ 72 chars>

<why, and what the user notices. Wrap at 80.>
```

- Scopes: `extension` (shared `plex-to-iina/` code), `chrome`, `safari`, `plugin`,
  `docs`, `tools`. Omit the scope when a change spans several.
- One logical change per commit. Don't mix a fix with a new feature.
- Mark breaking changes (for example settings that reset, or a reinstall being needed) with
  `!` after the type and a `BREAKING CHANGE:` line in the body.

Examples:

```
fix(safari): fall back to a link when the companion app doesn't answer
feat(extension): catch the play button on library-grid cards
qol(plugin): stop repeating progress reports while paused
perf(extension): reuse the resolved server for 10 minutes
```

## Pull requests and labels

For anything larger than a small fix, work on a branch named `<type>/<short-name>` (for
example `feat/episode-playlists`) and open a pull request. Label it to match the type:
`bug` for `fix`, `enhancement` for `feat`, `qol` for `qol` and `perf`, `documentation`
for `docs`. Squash-merge with a Conventional Commit title.

## Changelog and versions

- Every `fix`, `feat`, `qol` and `perf` change gets a line in `CHANGELOG.md` under
  **Unreleased**, in the matching section, written for users rather than developers.
- Versions follow SemVer: `fix` → patch, `feat`/`qol`/`perf` → minor, breaking → major.
- A release bumps the version in all four places, moves **Unreleased** to the new version
  with the date, and is tagged `vX.Y.Z`:
  - `plex-to-iina/manifest.json`
  - `safari/manifest.json`
  - `iina-plugin/plex-progress.iinaplugin/Info.json`
  - `VERSION` in `iina-plugin/plex-progress.iinaplugin/main.js`

## Before committing code

- `node --check` every JavaScript file you changed.
- `bash -n safari/build.sh` if you changed it.
- Plugin changed? Rebuild the package so the committed `.iinaplgz` matches the source:
  `cd iina-plugin/plex-progress.iinaplugin && zip -X ../plex-progress.iinaplgz Info.json main.js`
- Safari-side changes: run `safari/build.sh` to check it still builds.
- Plugin behaviour: test with `tools/mock-pms.py` (instructions at the top of the file).
- `safari/extension/` is generated by `build.sh`; never commit it.
